CSS Grid: auto-fill vs auto-fit

Ambos se usan con: repeat(auto-..., minmax(180px, 1fr)) para crear columnas responsivas sin media queries.

Objetivo

Entender cuándo se ve la diferencia entre auto-fill y auto-fit.

  • Si NO sobran columnas: se ven igual.
  • Si sobran columnas vacías: se comportan distinto.

auto-fit NO estira siempre.
Solo estira cuando tiene columnas vacías que pueda colapsar.

Demo A — auto-fill

Qué hace: crea todas las columnas posibles según el ancho disponible. Si no hay suficientes elementos, las columnas vacías siguen existiendo.

Eso significa que puede haber “columnas fantasma” ocupando espacio.

Qué está pasando técnicamente

repeat(auto-fill, minmax(180px, 1fr))

  • auto-fill calcula cuántas columnas caben.
  • Si caben 6 columnas, crea 6.
  • Aunque solo haya 3 tarjetas, las 6 columnas existen.
  • Las columnas sin contenido ocupan espacio.

Demo B — auto-fit

Qué hace: también calcula cuántas columnas caben, pero si sobran columnas sin contenido las colapsa.

Eso permite que las tarjetas se estiren y ocupen el espacio libre.

Qué está pasando técnicamente

repeat(auto-fit, minmax(180px, 1fr))

  • auto-fit también calcula cuántas columnas caben.
  • Si sobran columnas sin contenido → las colapsa (ancho 0).
  • El espacio libre se reparte entre las columnas que sí tienen tarjetas.
  • Gracias al 1fr, las tarjetas se estiran.

¿Por qué a veces se ven iguales?

Porque no sobran columnas.

Si tienes suficientes tarjetas para llenar todas las columnas que caben en el contenedor, no existen pistas vacías.

  • No hay columnas vacías.
  • No hay nada que colapsar.
  • auto-fill y auto-fit se comportan igual.

La diferencia depende del escenario.

Resumen

  • auto-fill : mantiene columnas vacías.
  • auto-fit : colapsa columnas vacías.
  • Si no hay columnas vacías : se ven igual.

Regla mental: “auto-fill reserva espacio, auto-fit lo aprovecha.”

Juega con el número de tarjetas y con el ancho de la ventana.
